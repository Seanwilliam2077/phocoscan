# 扫描 15：漂浮点、主体清理与耗时（2026-11-12）

后续挂绳/脚边清理与毛发保留检查见 [主体边缘优化记录](ON-DEVICE-TRAINING-V5.md)。本页保留 v4 的原始对照。

用户要求在 v3 基础上处理企鹅周围的漂浮细丝、底部散点及训练耗时；继续用扫描 15 对比，保留原素材、已有结果及恢复能力。此次没有云端任务、服务器修改或相机素材重写。

## 原因与改动

1. **重复 CPU 工作。** v3 每个训练视角到来都遍历完整 RGBA 图像，重算不会改变的遮罩面积。本轮按原始 imageIndex 缓存该标量，分辨率变化继续使用原始面积定义。缓存不属于优化器状态，重启可以从相同输入确定性重建。跨视角返回时的损失和逐像素梯度有完全相等的回归检查。短测 300 步 CPU 损失编码从 10.90 到 4.68 秒，但短测总时间 17.87→19.75 秒，没有宣称短测整体加速。
2. **异常长轴。** 新锚定主体任务将高斯最大轴/次大轴限制为 12，投影回约束后清空被调整轴的 Adam 状态。使用次大轴而非最短轴，保留扁平表面。原有暂停任务的可选 `lineAspectLimit` 为 nil 时不启用约束。该限制会影响表示能力，不代表所有超过阈值的高斯都是错误几何；必须用真实细节与留出视角检查取舍。
3. **底部包含真实桌面和多余散点。** 原查看器只用较宽的锚定包围范围，特意保留支撑面；提高训练主体权重不会自动从结果移除桌面。本轮保留完整 `scene.ply`，另外生成可撤销的 `subject.ply`，不以删掉完整模型的方式掩盖背景问题。
4. **多视角主体证据。** `TrainingSubjectSurface.swift` 只取至多 32 个训练视角，留出照片不参与主体选择。沿相同相机投影读取保守降采样的主体遮罩，给边缘留一格余量。至少 4 个可投影视角；中心须在至少 65% 的可见视角获得主体支持，旋转后的三个主轴各自正负 2σ 端点须得到至少 35% 的支持。首轮只检查最长轴，实际还留下扁平桌面碎片，因此补查全部轴并添加专门回归。输出只选择原参数，不修饰渲染图。少于 8 个有效分割视角或不足 100 个可见主体点时保留完整结果并使用原查看方式。
5. **原有界面。** 本机查看器的现有“主体 / 全景”按钮分别加载这份独立主体副本和完整模型，相机保持不跳动。已有结果没有副本时仍按原逻辑查看。共享完整 PLY 的行为不变，视频/实况渲染当前显示的内容。没有增加主界面文案或训练设置。
