## 已取得的真实证据

- Windows 可以读取指定 RealityScan Hub 的 OpenAPI 和 capabilities。服务返回 `engine:worldmirror2`、`type:gs_worldmirror2`、`available:true`，默认 `max_frames:16`、`target_size:518`，坐标为 `algorithm`，尺度为 `unknown`。
- 用户在 iPhone Safari 打开同一 capabilities 地址并返回上述 JSON，确认手机到 Hub 的 HTTP 网络可达。这不证明正式微信小程序允许使用 HTTP/IP 地址。
- Windows 可访问现有 PocketWorld 公网 HTTPS 后端；Codespaces 到内网 Hub 的 10 秒请求超时。采用 Windows 出站处理器连接两边。
- 创建了独立命名的合成测试组，并上传同一程序生成场景的 8 张多视角 JPEG（518×518，总计 601210 字节）。Hub 返回 `image_count:8`。
- 使用一次持久化 request_id 提交 quick-reconstruct，真实返回 HTTP 200、project_id 和 step_id。随后指定 `algorithm=gs_worldmirror2` 和本次 step_id 查询，真实状态为 `RUNNING` / `waiting_gpu`，尚无 PLY。
- 原始响应、文件哈希和本次任务标识保留在本机忽略目录 `work/worldmirror-smoke/`，不会随源码推送。
- 使用项目私有工具目录中的 FFmpeg 7.1，把这 8 张合成图编码为 8 秒 MP4，再通过实际 worker 抽帧函数验证：8 帧配置得到 8 张 JPEG，16 帧配置得到 16 张 JPEG；未接触用户视频，也没有因此再次提交 GPU 任务。

## 代码实现及验证边界

接口适配器保存写操作意图和固定请求标识，未知结果不盲目重新创建。处理器只操作显式选中的原生视频任务，核对视频哈希和来源，调用 FFmpeg 抽帧，并使用真实模型文件导入同一会话。取消和删除保护、重试、私有访问与状态卡另有自动化测试。

微信官方 WXML/WXSS 编译已通过：7 个页面，70 个小程序文件。模拟器首页可显示；页面自动化上下文请求出现超时，因此新增状态卡的真机排版仍须 iPhone 验证。

Windows 全量自动化测试 **224/224 通过**，其中 provider 28 项、Windows bridge 17 项；包括重试与未知结果、状态抢占冲突、输入哈希与 revision、取消后明确重新排队、网络暂时失败恢复、下载超时、同源导入及原有拍摄/养成规则。另已通过独立代码审查并修复所发现的提前 ready、来源检查缺失和并发误标 failed 问题。

本次真实 Hub 的 OpenAPI 没有声明成功状态枚举，测试任务仍未到达成功终态。适配器默认拒绝凭空假定 `SUCCESS`/`DONE` 就是成功；需由真实终态确认配置后，才允许自动下载和回填。mock 中的成功枚举只证明控制流，不是服务契约证据。

这里的测试素材是纯合成图像，不是手机扫描。FFmpeg 抽帧、接口 mock 和导入测试都不能证明 WorldMirror 实际成功输出、真实场景质量、实时性能或机器人可用性。
