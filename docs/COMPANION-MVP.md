# 扫描为目的，陪伴养成为载体

2026-10-22 用户澄清：需要玩家为了游戏而自发扫描，界面简洁；纯采集工具也不满足目标。

当前验证一条循环：小芽提出一个很小的愿望 → 玩家在室内或街景找一处静态角落 → 扫描并上传 → 小芽收到回忆并成长 → 真实重建结果回流，成为可打开的三维回忆 → 下一个小愿望。

## 界面与动机

首页只有一只小芽、一句愿望、一个扫描按钮。点击小芽可以获得轻互动，但不会增加扫描奖励。回忆、导入模型、设置放在次级入口。不恢复地图、九宫格、任务列表、商店和多种货币。

成长分为初见、发芽、展叶和开花四个可见阶段，对应 0、1、3、6 份被服务端接收的回忆。每一份回忆使用同一个真实会话和唯一奖励凭据，重试不重复成长；删除真实媒体后保留虚拟成长。首期没有饥饿惩罚、签到连胜或强制等待。

愿望一次呈现一个，覆盖有光的角落、休息区、小路、绿地、阅读角和日常空间；室内外均有替代地点。继续使用真实 quest ID 和已解锁规则，已有进度可恢复。愿望不会声称机器已经识别出画面内容。

## 反馈与数据

- 本地草稿不增长；源文件真正提交并取得服务端奖励凭据后，才产生基础成长。
- 基础成长鼓励完成采集；它不代表三维重建成功或机器人数据验收通过。
- 同一次扫描的原视频与导回模型继续按 session 关联。仅外部模型导入仍标记 external_asset_only。
- 只有真实导回模型存在才展示可看 3D；不使用倒计时生成结果。
- 即使处理失败，也不撤走虚拟成长，玩家仍可查看失败状态、修正或重试。

首轮验证：是否有玩家完成第二次、第三次自发扫描；上传成功率、可重建率、室内外覆盖、每个可用场景的人工处理成本。成长次数不能代替质量指标。

## 参考与取舍

参考 [Finch 的目标、陪伴与冒险循环](https://help.finchcare.com/hc/en-us/articles/42149821015693-New-User-Guide)：现实行动让伙伴前进，伙伴带回故事。本项目只保留伙伴、一个愿望和成长反馈。

参考 [Pikmin Bloom 的日常行为、养成与回忆](https://pikminbloom.com/)：把日常活动变成成长和可回顾的记录。本项目以真实扫描回忆连接虚拟成长，不接入 GPS 地图。

参考 [猫咪后院的观察与相册](https://www.nekoatsume.com/sp/en/about.html)：轻量互动和收藏本身可以构成回访理由。本项目保留观察小芽和三维回忆，不加入商店体系。

以上是设计假设，是否能促进自发扫描仍须由真实测试验证。
