## 0. 给实施 Agent 的任务

请实现《口袋世界》的 iPhone 原生 App MVP，把“领任务 → 实地探索采集 → 提交 → 处理 → 查看结果 → 获得场景卡 → 布置社区 → 下一次探索”的闭环做通。交付可在测试 iPhone 上安装的 App、可操作的游戏、真实文件流转和实施文档，不能只交付设计稿、模拟器截图或扫描动画。

用户最新优先级：

1. 最重要的是手机上的完整产品闭环和玩法验证。
2. 3D Gaussian Splatting（3DGS）重建可以接其他公司的软件，不要求本期自研或在手机本地实现重建算法。
3. 后续扫描、处理、预览、检查缺口、补采的流程参考 Scaniverse。
4. 保留未来“一次采集服务机器人与视频模型”的数据结构，但不要让完整机器人仿真或基础模型训练阻塞本轮交付。
5. **用户已明确排除 HTML 形式，并确认首轮测试手机为 iPhone。本轮玩家端锁定 iOS 原生 App；禁止交付 H5、PWA、浏览器网页或 WebView 套壳版本。**

**确定路线：Swift／SwiftUI 的 iPhone 原生 App。** 原生相机采集、应用私有文件存储、Metal 3DGS 查看；重建仍由可替换的第三方工具或服务负责。本轮不开发 Android 或微信小程序，也不重新让用户选择平台。

**交付方式：优先开发签名后直接安装到测试 iPhone；已有可用分发账号与权限时使用 TestFlight。** 本次不要求上架 App Store。只有工程源码、未签名 IPA、模拟器截图或后台网址均不算手机可运行交付。操作后台可用网页，玩家端必须保持原生。

已知测试平台为 iPhone；具体型号、iOS 版本及构建机是否具备 Mac／Xcode 尚未确认。实施时优先从连接设备和现有环境读取；将实际型号、系统与签名条件记入测试报告，不假设用户拥有 Pro／LiDAR 机型，也不据此阻塞普通 RGB 采集流程。

先查看现有仓库和运行环境，复用已有技术栈。没有现成项目时，采用本文默认架构。先做一条纵向闭环，再扩展全部章节。

## 1. 必须区分的三类结果

| 结果 | 达到什么才算完成 | 不能代替什么 |
|---|---|---|
| 手机产品闭环 | 真机领任务、实采或转接外部采集、结果回到游戏、查看真实资产、领取与放置卡片、进度可恢复 | 不自动证明数据可用于训练 |
| 数据可用性 | 自己采集的原始数据能经真实处理得到可用产物，来源可追溯 | 不以预置样例模型代替本次采集结果 |
| 数据双用途 | 同一来源具有可交付视频及可靠相机信息，并通过机器人视觉资产与视频两套验收 | 不以一个 `.ply` 文件或渲染视频证明全部条件 |

当前首先完成第一项。第二项至少跑一处室内、一处室外的真实样本。第三项允许后续验证，状态必须如实显示为未验证。

开发时可使用明确标记的演示素材，帮助验证页面和状态流转；演示素材不能计入真实闭环、采集质量或双用途指标。

## 2. 核心产品：为三位旅人建一座小驿站

用户价值：把日常遇见的室内外风景，变成自己社区中的收藏与建设材料。

核心循环：

```text
居民提出愿望
    ↓
玩家选择建设方向和可替代的探索地点
    ↓
手机探索一小片现实空间
    ↓
保存与提交采集，获得基础场景卡
    ↓
异步处理，回看真实结果，必要时选择补采
    ↓
将卡片放入社区，改变布局与居民互动
    ↓
解锁新的选择和探索动机
```

首版使用 2D 卡片建造。真实 3DGS 放在场景卡详情中供玩家旋转、缩放、回看，不需要将所有真实场景自动融合成一个可漫游的 3D 城市。

卡面附玩家自己采集的风景邮票、标题与日期；游戏建造主体使用少量预制插画或代码绘制的图形。真实影像默认私有，分享默认只包含虚拟社区。

### 2.1 最少内容

- 一个九格社区；首版支持移动、放置、旋转、撤回卡片。
- 三位可互动居民：邮差阿灯、画师、小摊主／园丁角色之一。
- 至少八种可用卡：入口、邮局、道路、门厅、休息区、绿地、阅读角、小摊位。
- 道路提供必要的直路、转角、三岔或十字变体，允许旋转。
- 至少六个可完成任务，覆盖首次探索、新地点探索、补采和纯建设。
- 一段开站庆典和至少两个下一章选择。
- 内容从配置读取，不把“第几天”硬编码为等待多少小时。

### 2.2 建造规则必须有真实选择

1. 道路按四邻接建立连通关系；如实现道路接口，旋转后接口也须对应。
2. 邮差希望入口能连到邮局与休息区。
3. 画师喜欢休息区邻接绿地，且不与小摊位直接相邻。
4. 小摊主喜欢靠近入口；首版可用网格距离表达。
5. 条件影响居民表情、对话和事件，不使用惩罚式体力或强制签到。
6. 玩家可以通过调整已有卡片解决问题，不把每个布局问题都设计成“必须再拍一次”。

示例布局如下；实施者需用实际规则验证它可完成目标，不要照图实现不一致的连接逻辑：

```text
入口    三岔路    小摊位
邮局    十字路    阅读角
空地    休息区    绿地
```

场景卡的道路形状和语义属于游戏规则，不等于现实场景的导航几何或已验证语义标注。

## 3. 从首次打开到第 7 天的完整体验

首次打开记为 D0；D1—D7 是后续观察日期。下表是示例体验路径，章节按进度解锁，玩家可提前、推迟或选择其他地点完成。允许某一天只建设、不采集。

| 阶段 | 玩家体验与任务 | 持续玩的理由 | 对应采集与限制 |
|---|---|---|---|
| D0 首次打开 | 选择“花园小站／热闹街坊／安静旅店”，命名社区，放置免费入口、道路和邮局。阿灯希望有等信的地方；玩家选室内门厅或室外休息区。完成第一次探索，拿到卡片，阿灯入住 | 几分钟内看见自己做出的选择，拥有第一个居民 | 一处局部场景；示例选择获准拍摄的室内玄关。首次授权后才开始录像 |
| D1 室外发现 | 阿灯带来两位访客，玩家选画师。午休探索街角休息区，把“树荫休息区”放在画师旁边 | 自己选择下一位居民，日常街角变成私人收藏 | 围绕长椅、铺装等固定参照缓慢换位置；避开以路人、车辆、天空为主体的画面 |
| D2 布局问题 | 休息区与主要通路冲突。玩家可重排已有卡，或探索短走廊取得另一张通路卡 | 新卡提供一种布局解法，而非仅增加数量 | 室内通道；保留门框、墙角和地面的共同参照，不以一个片段冒充整层楼 |
| D3 纯建设 | 看画师送给邮差的肖像，改配色、移动长椅，两分钟后退出 | 已有世界本身有价值，回来不必立即做采集任务 | 没有场景采集；记录游戏回访，不能记为采集回访 |
| D4 完善收藏 | 玩家喜欢已有休息区。若确有覆盖缺口，提供“补全另一面”，展示参考截图和具体观察方向；也可选择新地点 | 完善自己已经用上的作品，奖励可选边景或装饰 | 新会话与旧会话关联；只有对齐验证通过才算补全。没有几何检测时显示“建议补拍／待审核”，不虚构缺口检测 |
| D5 发展选择 | 选择“小集市”或“花园步道”。任务允许室外绿化区域或获准室内植物休息角替代；示例选新的街角花坛 | 社区开始有个人风格，玩家决定发展方向 | 关注花坛边缘、路面与固定背景；动态植物区域另行处理。必须去重后才算新空间 |
| D6 室内外组合 | 通过已有卡或一次新的室内阅读角探索，完成“阅读角＋花园步道＋道路”的读书会组合 | 此前收藏形成整体，旧卡继续有用 | 示例增加第二种室内空间；游戏卡片连接不代表真实场景已完成拼接 |
| D7 开站庆典 | 居民沿玩家布置的路线参加活动，生成虚拟社区纪念卡；选择接待旅人、扩建花园或开店 | 得到阶段成果，并自主选择下一步 | 不强制当天采集。庆典动画不是训练视频；只有主动新探索才计入采集回访 |

示例中约有五次新场景探索、一次补采。不得把这六次写成强制每日清单。用户晚几天完成仍能看到完整故事。

### 3.1 第一次探索的具体交互

任务名：“找齐三枚邮戳”。目标时长约 60—90 秒，可延长、暂停或放弃；时长不是质量保证。

1. **选一处：** 玩家选择局部目标，确认适合拍摄；只扫描几步范围的固定场景。
2. **第一枚：** 稳定观察正面，检查录像、曝光与画面可用性。
3. **第二枚：** 提示从侧面观察，并让前一处固定参照留在画面里。
4. **第三枚：** 从安全位置调整高度，补充地面和边缘观察；不要求钻入桌下或进入危险区域。
5. **收尾：** 选择一帧做风景邮票，预览视频，允许重拍、删除或提交。
6. **奖励：** 通过本地基础检查并可靠保存后给基础卡；云端失败不收回已有卡。真实结果返回后解锁场景回看和额外图鉴信息。

iPhone 原生 App 首版允许使用屏幕内提示和分步骤确认。未启用可靠空间跟踪时，不把邮戳伪装成准确锚定现实的 3D 对象，不把按钮确认或录像时长当作有效视差证据。实时空间谜题、自动覆盖计算可以后续接 SDK。

## 5. 技术路线：先跑通，再替换重建供应商

### 5.1 默认架构

```text
iPhone 原生 App（SwiftUI）
  ├─ 2D社区 / 角色 / 任务 / 本地草稿
  ├─ 手机相机视频采集或外部扫描转接
  └─ 3DGS结果查看器
          ↓ HTTPS
轻量后端
  ├─ 用户与游戏存档
  ├─ 采集上传 / 任务状态 / 事件记录
  ├─ 私有文件存储与下载
  └─ ReconstructionProvider
          ├─ manual：人工处理、登记真实结果（首期默认）
          ├─ vendor：将来接真实第三方 API
          └─ demo：演示素材，仅开发与教程使用
```

玩家端固定采用 iOS 原生路线。后端使用熟悉的轻量框架，数据库可从 SQLite 起步；复用现有对象存储或私有磁盘目录，不先搭微服务。固定依赖版本并保留 `Package.resolved` 等锁文件。

| 模块 | 本轮技术选择 | 约束 |
|---|---|---|
| 游戏与界面 | Swift／SwiftUI；九格社区与轻量角色动画 | 竖屏、触控、适配安全区；不引入 H5 |
| 基础采集 | AVFoundation 真实视频录像 | 后置摄像头；音频默认关闭；原始像素无游戏 UI |
| 位姿增强 | ARKit 图像、相机信息与时间戳 | 能力验证后启用；与视频使用同一采集源，缺失数据明确标记 |
| 本地数据 | 应用私有文件目录＋适当的结构化存档 | 大视频与小存档分离，文件保存与上传重试可恢复 |
| 结果查看 | Metal／MetalKit＋已验证的原生 splat 渲染库 | 真机加载真实资产，不用 WebView 代替 |
| 文件与网络 | 系统文档选择器、原生网络请求与后台任务状态查询 | 输入来源可追溯；后端 HTTPS；处理可由操作者人工转接 |

原生查看器先验证开源 MetalSplatter 的样例与一份小型真实资产。该项目提供 Swift／Metal 实现；所选版本的最低 iOS、Xcode／Swift 要求、格式与许可须核对并固定。[S7] 不先把部署目标写死为任意新系统；以测试 iPhone 和依赖可支持的交集为准。无法支持目标设备时明确定位兼容问题，不静默改成网页或更换用户测试平台。

### 5.1.1 iOS 构建与安装前置检查

1. 检查是否有可用 Mac、兼容 Xcode、iPhone 真机与签名 Team；记录 Bundle ID、部署目标和所选依赖版本。[S10]
2. 优先先把一个最小原生 App 安装到测试 iPhone，再继续扩充玩法；按实际 iOS 要求完成信任／开发者模式等配置。
3. 实测约 90 秒录像、私有目录保存、系统文档导入和 Metal 小资产查看。模拟器不代替相机与性能验证。
4. 有可用 Apple Developer／App Store Connect 分发权限时可使用 TestFlight；分发账号或签名凭证不写入仓库。[S11]
5. 如果另一台电脑只有 Windows／Linux，可先做后端与非 iOS 平台依赖的协议工作，但必须安排可用且已授权的 Mac 构建环境。报告实际缺少的构建／签名条件，不能把 Android、微信小程序或 HTML 作为本轮替代交付。

### 5.2 两条真实采集路径

**路径 A：游戏内采集 → 外部软件重建 → 游戏内查看。优先实现。**

1. App 原生相机模块打开 iPhone 后置摄像头，记录无游戏 UI 的真实视频。
2. 上传视频与任务元数据，形成待处理任务。
3. 操作者下载该任务的采集包，交给已验证支持此输入的软件或服务处理。
4. 操作者将该次采集产生的真实 splat 文件导入后台，填写来源和处理记录。
5. 手机端获取结果，打开 3DGS 查看器，回到卡片与建设。

这条路径要先用一个短样本验证供应商的实际输入能力。**不能假设 Scaniverse 可以接收任意普通手机 MP4 并重建，也不能编造上传 API。** 如果选定软件不支持本应用导出的视频，换一个输入兼容的处理工具，或明确使用路径 B。

**路径 B：游戏领任务 → 外部扫描 App 采集与重建 → 返回游戏导入。作为可交付备用路径。**

1. 游戏保存任务编号、室内／室外类别与拍摄指引。
2. 用户切到 Scaniverse 或其他已验证可用的扫描 App，实际采集并处理。
3. App 通过 iOS 系统文档选择器或已实现的分享接收入口导入本次结果；若供应商只支持桌面导出，也允许操作者从后台导入，再由 App 下载。
4. 游戏绑定任务编号，预览真实资产，发放或升级卡片。

路径 B 不要求尚未证实的深链或 SDK；手动切 App 与文件导入可以作为首期转接。外部采集期间本应用不能声称仍在同步录像、展示 AR 谜题或获得精确轨迹。把跳转、返回、导入失败和耗时纳入漏斗。

路径 B 若只能获得处理后的模型，则标为 `external_asset_only`。它可以验证产品闭环，不能证明掌握了原始视频与轨迹，也不能证明“一份数据双用途”。不要让用户额外拍一遍视频，再把两次采集说成同一来源。

**默认实施选择：做通路径 A 的真实手机录像与人工结果导入，同时实现路径 B 的资产导入入口。最终至少用一条真实路径完成室内、室外各一次，不以“以后接 API”作为完成闭环的理由。**

### 5.3 Scaniverse 参考范围与已知边界

参考其“采集 → 保存 → 处理 → 查看 → 检查覆盖 → 补采／重处理”的流程。Classic 与 New 体验的本地／云端处理、账号与导出路径不同，不应混为一个 API。[S1][S2]

官方当前 360 上传文档明确的是 `.insv` 或等距柱状全景 `.mp4`，不能据此推断任意普通手机视频可直接上传。[S3]

官方资产检查流程包含查看缺口、下载支持的资产、添加针对性补采并重新生成资产版本。实现借鉴此状态与操作逻辑，不复制品牌、界面或私有接口。[S2]

官方社区工作人员在 2026 年 5 月的答复称，当时 App 不支持导出／转移原始采集数据；这属于对应版本与路径的说明，实施时应复核。默认不能将“保存 raw data”理解为“第三方可以取得这些数据”。[S4]

无需为本 MVP 实现 VPS 定位。使用第三方账号、付费资源或受限接口时遵循已有权限与实际可用条件；不要把购买付费服务当作未说明的前置条件。

## 6. 手机采集与结果查看的工程要求

### 6.1 iPhone 原生相机采集

- 使用 AVFoundation 或 ARKit 图像流，正确配置相机用途说明与原生授权流程，处理拒绝及再次授权。[S5][S12]
- 优先后置摄像头；音频默认关闭；用户主动开始时才录制，结束／离开时释放摄像头。
- 视频记录相机流，游戏提示是独立界面层，不能把整屏录屏当原始视频。按实际编码保存 MIME 和扩展名。
- 目标为约 1080p、30fps，但记录设备实际分辨率、帧率与编码；不支持时允许明确降级。
- 首期探索建议 60—90 秒，先在目标 iPhone 验证录制与中断行为；处理工具需要更长采集时允许配置时长，不为游戏节奏伪造质量达标。
- 暂停／中断时记录片段边界；App 切入后台、锁屏、来电中断、被系统终止或权限撤销时给出可理解的恢复结果，不承诺后台继续录制。
- 视频存入可持久保存的应用私有文件目录，不仅保留临时路径。小型存档与大文件分开存储。
- 保存原始文件并支持预览、删除与重试上传。上传成功前不要清空唯一副本；处理磁盘空间不足，退出重进后检查文件实际存在性。
- 后端请求和文件传输使用 HTTPS；这属于网络接口要求，不将玩家界面改回网页。
- 原生录像本身不等于已有可靠内参或 6DoF 轨迹。未实际启用并验证 ARKit／供应商能力时，缺失字段留空，不通过 GPS、设备转角或编造数值补齐。
- 使用 ARKit 同时取得帧与相机信息时，从同一 ARSession 图像源编码视频并记录映射。[S12] 不要同时启动独立相机采集会话争用摄像头，或拼接不同时间源的参数；首期可先使用真实 RGB 录像。
- 保留视频帧与时间戳对应关系，注明坐标轴、单位、位姿方向和矩阵存储约定；视频旋转、缩放或裁剪时同步调整内参。跟踪失效需标记或切段。LiDAR／深度为可选增强，不作为首轮 iPhone 普通录像的前提。

### 6.2 初级质量提示

可实现亮度、模糊、录像时长、视频可解码等轻量检查，但显示为提示或基础检查结果。没有可靠空间跟踪时，侧移完成只能记为用户确认／待审核，不能宣称已测量视差或完整覆盖。

首期真人指引强调：缓慢移动；不同位置观察同一区域；保留固定参照；补充地面；避免拍摄无权限内容。只对用户选择且可安全观察的局部区域提出任务。[S6]

### 6.3 3DGS 查看器

- 必须能用触控旋转、缩放，支持重置视角与退出，至少加载一种真实 splat 格式。
- 区分 Gaussian PLY 与普通点云／网格 PLY；扩展名相同不代表内容相同。
- 显示加载状态、资产大小与可理解的失败原因；失败可重试，不白屏。
- 小资产优先；只同时加载一个模型，退出时释放 GPU 资源。
- 在至少一款目标真机上记录加载时间、交互表现和内存相关故障。大资产降采样／压缩可在外部处理，不需要自研算法。
- 硬件不支持时可以回退到封面和外部查看，但这种回退不能被记为“App 内置 3D 查看器已验收”；不能靠嵌入 H5 查看器满足该验收项。
- 查看器展示的真实资产必须与该任务来源一致。预置示例在界面与记录中明确标为示例。

## 7. 页面与状态：必须能独立操作

| 页面 | 最少功能 |
|---|---|
| 首次进入 | 产品说明、社区主题和命名、用途说明、开始试玩 |
| 我的社区 | 九格布局、卡片放置／旋转、居民反馈、当前目标、存档 |
| 任务详情 | 故事目标、可替代地点、室内外选择、拍摄指导、采集方式 |
| 手机采集 | 相机画面、开始／停止、步骤提示、退出、权限与中断处理 |
| 采集预览 | 视频播放、风景邮票、重拍／删除／提交 |
| 任务记录 | 草稿、上传、等待处理、失败、结果可用；返回后可恢复 |
| 场景卡详情 | 来源、封面、真实结果查看、补采入口、领取与放置 |
| 庆典与下一章 | 角色反馈、纪念图、下一步选择 |
| 操作后台 | 待处理列表、采集包下载、真实结果导入、状态与审核记录 |

### 7.1 状态分层

不要把游戏通关、文件处理、数据质量混成一个 `success`。

```text
游戏：offered → accepted → explored → base_rewarded → placed → chapter_advanced

内部采集：draft → recording → saved → uploading → submitted
外部转接：draft → external_capture_pending → awaiting_asset_import → asset_imported

处理：not_requested → queued → processing → ready / failed / cancelled

质量：not_assessed → needs_review → accepted / rejected

双用途：not_evaluated → partial → accepted / rejected
```

- 手动处理模式里，“processing”由操作者真实启动，不按倒计时自动变成“ready”。
- 只有结果文件成功登记且可读取，才能进入“ready”；只有审核完成才改质量状态。
- 基础奖励按可靠保存／提交的任务条件发放；重复点击、上传重试和重复回调不能重复发卡。
- 外部扫描路径在导入文件通过基本格式与可读取性检查、登记本次任务来源并绑定 session 后，进入 `asset_imported → explored → base_rewarded`；按 session 幂等发奖，不等待训练数据质量或双用途验收。导入失败时保留任务并允许重试。
- 云端失败不撤销已放置的基础卡；结果增强、补采奖励与基础奖励分别处理。
- 补采有独立 session，关联原场景与原任务；未成功匹配前不声明完成拼接。

## 8. 最小数据模型与转接接口

命名可随技术栈调整，但含义与来源标记必须保留。下列 TypeScript 仅表达数据接口字段，不要求玩家端采用 Web 技术；iOS 工程转换为对应 Swift 数据结构。

```ts
type CaptureMode = 'in_app_rgb' | 'external_app' | 'demo';
type Provenance = 'device_capture' | 'external_asset_only' | 'demo_fixture';

interface CaptureSession {
  id: string;
  userId: string;
  questId: string;
  sceneId: string;
  parentSessionId?: string; // 补采关联
  environment: 'indoor' | 'outdoor' | 'unknown';
  captureMode: CaptureMode;
  provenance: Provenance;
  capturedAt?: string;
  submittedAt?: string;
  originalVideoId?: string;
  videoDurationSeconds?: number;
  videoMimeType?: string;
  width?: number;
  height?: number;
  fps?: number;
  poseSource: 'none' | 'arkit' | 'offline_sfm' | 'vendor' | 'simulated';
  calibrationAvailable: boolean;
  rawDataAvailable: boolean;
  consentVersion?: string;
}

interface ReconstructionJob {
  id: string;
  sessionId: string;
  provider: 'manual' | 'vendor' | 'demo';
  status: 'queued' | 'processing' | 'ready' | 'failed' | 'cancelled';
  vendorJobId?: string;
  errorCode?: string;
  errorMessage?: string;
  resultAssetId?: string;
}

interface SceneAsset {
  id: string;
  sourceSessionIds: string[];
  kind: 'gaussian_splat' | 'mesh' | 'point_cloud';
  format: string;
  storageKey: string;
  sha256: string;
  provenance: Provenance;
  reconstructionTool: string;
  reconstructionVersion?: string;
  lineageStatus: 'declared' | 'verified';
  qualityStatus: 'not_assessed' | 'needs_review' | 'accepted' | 'rejected';
  dualUseStatus: 'not_evaluated' | 'partial' | 'accepted' | 'rejected';
}
```

### 8.1 必须保留的接口能力

可采用 REST 或已有项目风格，至少包括：

- 创建与读取任务／采集会话。
- 上传真实视频或导入外部资产，支持失败重试与幂等。
- 下载对应会话的采集包，记录实际可用字段与缺失字段。
- 创建处理任务，查询状态。
- 管理员导入真实处理结果，并绑定原 session／job。
- 玩家领取卡片、更新布局、保存居民与章节进度。
- 记录和导出实验事件。
- 删除本人采集及其派生资产引用，记录处理结果。

`ReconstructionProvider` 至少封装提交、状态查询、结果读取和失败信息。`manual` 与将来 `vendor` 实现返回同一内部数据结构；业务代码不要散落供应商专有字段。

### 8.2 原始数据与资产目录

```text
session_<id>/
  manifest.json             # 任务、来源、用途、设备与缺失字段
  capture.mp4 或 capture.mov # 有原始视频时保留实际格式，以真实编码为准
  preview.jpg
  events.jsonl
  camera.jsonl             # 仅实际取得或离线估计后才生成
  processing.json          # 软件、输入、输出、耗时、人工操作
  result/
    scene.spz 或 scene.ply
    quality.json
```

所选采集实现没有可靠逐帧位姿时，不生成假 `camera.jsonl`。启用 ARKit 或供应商相机数据后，应包含逐帧时间对应、内参、坐标系与变换约定、跟踪状态、分辨率及裁剪／旋转变换。离线估计位姿必须标注估计来源、尺度是否确定与置信信息，不能当测量真值。

外部模型文件、模型渲染的视频和现场相机原始视频分别分类。不能把 splat 绕转导出的视频当作真实采集母数据。

## 9. 手动处理后台要真正可用

首期允许后台由研究者操作，这不是假重建；前提是实际处理了对应来源，并返回真实结果。

操作员流程：

1. 看见待处理任务、室内／室外、原始文件和任务编号。
2. 下载采集包；核实供应商支持输入，执行实际重建。
3. 记录工具、版本／模式、开始结束时间、实际成本或待补录项。
4. 上传结果文件，检查格式、基本可读取性与来源关联。
5. 填写通过／需补采／失败及原因；文件可看不等于数据已合格。
6. 手机端收到可用结果状态，允许查看与继续游戏。

若从外部 App 转接，只导入该次真实扫描资产；记录来源为 `external_asset_only`，原始视频、轨迹能力按实际情况标记。

后台必须有独立访问控制；玩家只能访问自己的采集与资产。管理员凭证不能放玩家客户端，不能提供任意用户可更改任务状态的公开接口。下载使用受控地址，文件导入校验类型与大小，第三方 URL 不作为任意服务器抓取入口。

## 10. iPhone 安装／测试分发与真实验收

### 10.1 交付入口

- 提供已安装到测试 iPhone 的开发签名版本及重装说明，或实际可用的 TestFlight 入口；记录 Bundle ID、构建号、支持系统和签名方式。普通未签名 IPA 或一个源码仓库不能直接充当用户可安装版本。
- 根据所用签名方式说明目标设备条件、安装步骤和测试版本的有效期／限制；不要求公开发布 App Store，不默认必须购买新的服务。
- 本轮只交付 iOS 玩家端，其他手机平台不属于验收范围。
- 后端与上传／下载接口在手机上实际可达，不使用指向开发电脑 localhost 的客户端配置；给出后端部署及测试账号说明。
- 若没有可用 Mac、签名或 TestFlight 权限，先完成可执行的工程、配置模板与其余可测工作，准确列出最终缺少的条件。不得将模拟器预览报告为真机验收通过，也不得自行改成 HTML 或其他平台交付。
- 本地社区与任务草稿可离线保存，上传、处理和结果下载需要按实际网络能力工作；断网时保留任务并显示可恢复状态。

### 10.2 真机测试脚本

1. 新用户在测试 iPhone 安装并启动原生 App，命名社区并完成一次布局。
2. 选择室内任务，拒绝一次相机权限后能恢复；授权后真实录制。
3. 预览，保存并提交；关闭并重新启动 App 后，任务和文件状态仍存在。
4. 操作者完成真实处理或外部扫描结果转接。
5. 手机打开对应真实 3DGS，旋转、缩放、返回，领取并放置卡片。
6. 在另一处室外空间重复核心链路，记录动态遮挡等问题。
7. 模拟一次上传失败与重试、一次处理失败；不重复发奖、不丢失社区。
8. 完成纯建设章节和补采入口；补采保留独立来源关系。
9. 完成庆典，选择下一章；导出日志。

必须记录测试 iPhone 型号、iOS 版本、App 构建号、Xcode 与主要依赖版本、测试日期、采集模式和已知问题。模拟器不能替代真机摄像、文件导入和 Metal／GPU 测试；补充记录模型加载、交互卡顿、发热和内存故障。

如果实施 Agent 无法接触真实手机，应完成可构建工程、能够生成的安装产物和后端部署，再提供这份脚本及待测项，等待真实执行结果后修复；不能编造安装或真机通过记录。

## 12. 开发顺序：不要最后才发现手机上跑不通

### 里程碑 1：先验证最难链路

先完成测试 iPhone 的签名安装与启动，再做一次真实录像或外部文件导入、App 内 Metal 真实 splat 查看和结果保存。确认至少一种输入到输出路径可用。不要先花数天制作全套剧情动画；不要用网页查看器掩盖原生渲染尚未接通。

### 里程碑 2：一个完整任务

实现命名社区 → 阿灯任务 → 采集／转接 → 基础卡 → 后台真实结果 → 手机查看 → 放置卡片 → 阿灯入住。处理失败、权限拒绝和重试一起做。

### 里程碑 3：形成可重复玩法

加入道路与居民偏好、第二类场景、下一位访客、补采、纯建设章节。让新卡确实提供新的布局选择。

### 里程碑 4：第一周内容与观察

配置 D0—D7 的故事路径和庆典；补齐事件记录、小后台、测试与手机兼容性。开发者可快速跳章节，但真实研究事件不能使用修改日期伪造留存。

### 里程碑 5：供应商自动化与高质量数据

在产品闭环跑通后，再替换人工处理、接 SDK／API、增加可靠相机轨迹与覆盖验证。此阶段不得反过来阻塞首版手机可运行交付。

- 能否在没有口头帮助时完成第一张卡；卡在哪一步。
- 是否理解新卡能解决什么建设问题。
- 是否主动做第二次探索；拒绝的原因是无聊、操作麻烦、地点受限、等待处理，还是隐私顾虑。
- 外部 App 转接损失多少用户；回来后能否找到未完成任务。
- 3D 结果是否让玩家更重视自己的收藏，还是只看一眼就离开。
- 室内、室外各自的失败原因、处理耗时、人工分钟数。

后续需要正式对照时，再比较“普通引导采集”和“探索＋建造”，保持两组技术能力、研究补贴与触达一致。游戏回访、主动采集、每人新增合格空间分开统计。不要按扫描数量或 D7 回访发研究补贴来证明自然留存。

## 14. 数据双用途的后续接口，不是首版完成声明

长期目标仍是同一连续探索视频服务两条管线：

- 机器人侧：清晰关键帧与位姿 → 静态场景重建 → 限定视域的视觉资产；碰撞几何单独验收。
- 视频侧：真实连续视频＋对应轨迹／内参＋场景描述 → 镜头控制与空间一致性数据。

CameraCtrl 的官方实现提供视频、相机轨迹与字幕输入的参考；VR-Robo 展示 3DGS 与网格结合的机器人环境方向。[S8][S9] 它们不证明本项目的数据已经可用。

本轮 iPhone 原生录像在尚未启用相机参数导出时，可能只有真实视频；外部 App 导入可能有 splat 但没有原始视频。两者都要如实记录。选择供应商时，应优先核实原始视频、相机参数、使用授权、导出能力及费用，再谈“一份采集两种用途”。

手机胸口高度观察不能自动覆盖低矮机器人的视域；漂亮重建不能直接作为碰撞几何；静态场景探索也不提供机器人动作、力矩或接触真值。

## 15. 实施 Agent 的最终交付格式

完成后请给用户：

1. 可实际用于测试 iPhone 的签名安装方式或有效 TestFlight 入口，以及安装步骤。
2. 已实现玩法列表，以及一条从首次进入到结果回到社区的演示路径。
3. 真实采集与重建接法：使用哪个工具、支持什么输入、哪些环节人工完成。
4. 一处室内、一处室外的真实测试结果；未完成时明确具体缺失条件。
5. iOS 源码、Xcode 构建／签名／安装说明、配置模板、后台入口和真机测试记录。

不要将“生成了代码”“构建成功”“模拟器截图正常”单独当作完整完成。最终需要让用户能够在 iPhone 原生 App 中实际玩一轮，并看到属于这次采集的结果回到游戏。
