2026-11-10。基于本机 `/Users/seansiu2077/Downloads/AgeScan` 的源码与设计文档；AgeScanCore 在独立临时构建目录执行，189 项测试通过。未安装或启动同事的服务器服务，未运行真实重建，未复制其实现进 phocoscan。下文性能收益是待验证的预期，不是两款 App 的实拍对比结论。

## 建议优先结合的能力

| 优先级 | AgeScan 已有实现 | phocoscan 的结合方式 | 验收 |
|---|---|---|---|
| P0 | CoverageGrid 按关键帧入选结果更新；CaptureProcessor 只有 decision == .accept 才点亮格子 | 保留我们的红绿 LiDAR 回看和锚定圈，但“已拍到”必须绑定有效且保存成功的关键帧。轨迹走过与有效素材覆盖分开 | 快速晃动、模糊、曝光不足时，不应仅因走满一圈就提示完整 |
| P0 | ProjectActions 按未上传、暂停、过期、失败、取消、已有结果给出可用动作；错误表提供具体建议 | 统一展示“上传—核验—等待资源—重建—下载—进入空间”；忙时稍后重试，下载失败仅重新下载，素材不足提示补拍 | 每个失败状态只有一个明确主动作；重试不重复创建任务或丢失已有结果 |
| P0 | 作品卡已有模型时直接进入查看器，详情作为次级入口 | 以“进入 3D 空间”为结果主入口，原片与视频导出放次级操作。本轮已调整详情页与查看器默认相机 | 结果进入后可直接交互；空间可环顾、移动；不默认沿拍摄轨迹播放 |
| P1 | 输出 PLY + SPZ；SPZ 下载、按任务缓存、离线打开；模型大小和点数在卡片显示 | 保留原始 PLY/SH3 与来源校验，增加适合手机分发的 SPZ 衍生结果。协议、哈希、相机轨迹都绑定对应版本 | 测量文件体积、首帧、峰值内存；校验颜色、尺度、旋转、SH 阶数；断网能打开已校验结果 |
| P1 | SfM 注册比例、位置对齐残差与朝向误差检查，不合格时回退 ARKit | 借鉴质量检查；失败时建议用户另选“位姿版”，由用户确认，不静默把高质量版换成位姿版 | 在同一新扫描上比较两种位姿来源；保留独立算法与结果身份 |
| P1 | COS 临时凭证、按文件/分片恢复、清单最后提交；上传可暂停 | 保留我们已验证的原视频断点续传。后续把关键帧包拆成可复用文件清单，按需求上传，避免反复上传相同素材 | 中断、凭证更新、服务端缺文件、清单不一致均可恢复；视频和关键帧仍同源 |
| P2 | TripoSplat 单图生成 3DGS，预测初始视角；推理子进程空闲后卸载模型 | 可作为单独的“图片生成”入口，标明 AI 生成；和扫描的真实采集来源分开。共享结果查看、导出和作品库 | 不把生成的背面或尺度当作实测数据；验证服务器资源占用和可取消性 |

## phocoscan 应保留的特点

- 同一原片、ARKit 位姿、内参与 LiDAR 的来源关联，以及手机本机训练。
- 扫描过程中的红绿观察几何反馈、人物分高度引导、空间回到起点的引导。
- 快速版、高质量版、位姿版、本机版的独立选择和结果保留。
- 主体裁切、完整 SH3 结果、可交互查看与可选视频/实况照片导出。
- 极简主路径：开始扫描 → 查看素材 → 选择重建方式 → 进入空间。

## 不宜直接照搬

1. AgeScan 的发现页、Mesh 生成在当前设计中有占位内容，不应把未实现入口搬进 phocoscan。
2. 覆盖率球是视角统计，不是表面完整性判断；同一球形目标不能直接用于人像和室内空间。
3. AgeScan 的 fast/fine 是同一 Spirula 训练器的不同迭代与规模档位（配置 7,000/30,000 轮）；不是我们的 FF 与独立 SfM→MCMC，两者不能按名称直接映射。
4. AgeScan 现有重建配置也固定 GPU UUID，单图方案设计也指定卡号；它不能直接解决此次“任意空闲 GPU”的要求。
5. AgeScan 的 SfM 回退捕获范围较宽。资源不足、服务错误和几何不合格应分别处理，避免把系统故障误当成算法回退条件。
6. 模型压缩后的 SH、坐标与来源需要验证；不能因为文件能打开就宣称保留全部高质量结果。
