# iPhone 扫描 App + FF 预览：首版交付范围

> 2026-11-03 最新补充：FF 快速预览仍可独立交付，同时将 SfM → 3DGS 精细结果、手机 SH3 渲染、版本切换与轨迹游览纳入后续交付验收。详见 [FF／SfM 与手机渲染方案](FF-SFM-MOBILE-DELIVERY.md)。下文描述已有 FF 主线，不能据此宣称新增精细分支已经实现。游戏只做轻量的成长记录。

## 用户在手机上的一条完整路径

1. 打开 App：直接看到最近一次扫描和一个醒目的「开始扫描」。服务器配置放在次级设置中；首次需要连接时给出清楚的状态和操作。
2. 选一处静止、有纹理的物体或场景：同一目标留在画面中，缓慢侧移，补一个斜角。室内和室外使用同一流程，不要求围绕目标转满一圈。
3. 拍摄时：显示真实录制时间、帧数和 ARKit 跟踪异常；用三句短提示引导视角。提示只能来自实际测量或明确标为操作建议，不能把倒计时当覆盖率。
4. 停止后：先在本机保存可恢复的原片、逐帧时间／相机内参与位姿，设备实际提供时另存深度。立即进入本次采集详情，可播放原片、查看上传状态。
5. 用户同意后上传：业务服务器核验视频与元数据，回执解锁一格小芽成长。这表示采集确实送达，不表示 3D 质量合格。
6. 原片核验通过后自动提交 FF：服务器为同一个 `captureId` 排一次 FF 任务；App 显示排队、处理中、可查看或失败。提交失败时可手动重试；允许用户离开页面并在回来后继续查询。FF 的实际耗时由上传、排队、推理和产物传输共同决定，不承诺实时完成。
7. 结果就绪：App 下载有大小上限、经 SHA-256 核对的 `.splat` 展示副本，在现有 Metal 查看器中旋转、缩放。原始视频、FF 原始 PLY 和展示副本分别保存，结果默认「待人工检查」。失败时保留原片并给出重试／补拍建议。
8. 新增计划：用户可发起精细处理，独立 SfM → GS 结果生成后下载保留 SH3 的版本，在同一详情中切换和沿匹配拍摄轨迹游览。精细任务失败不影响快速版；重建两次也只按同一真实采集计一次成长。此步骤尚待实施和真机验收。

首轮观察重点是**第一次能独立完成**，以及用户是否愿意再拍第二、第三处。成长记录为轻反馈，不引入农场经济、地图或强制任务。

## 系统边界

```text
iPhone 原生 App（SwiftUI + ARKit）
    本地 .scan：video.mov + frames.jsonl + manifest.json + 可选深度
        │ 用户授权、HTTPS、固定 captureId、哈希核对
        ▼
PocketWorld 业务服务：私有原件 + v2 核验回执 + FF 任务状态
        │ 操作员／出站 worker：解码、选择 8／16 张多视角图像
        ▼
RealityScan Hub / WorldMirror2：一次 FF 推理 → Gaussian PLY
        │ 核对固定输入、真实成功状态、结构和来源
        ▼
业务服务：有损轻量 .splat → iPhone Metal 预览
```

手机只访问自己可达的稳定 HTTPS 业务入口；Hub 地址和管理员凭据不进 App。FF 任务与上传回执分离：视频上传成功时立即给真实回执，FF 失败不抹除原片或回执。一个 `captureId` 对应一次首版 FF 请求，重复点击只取回同一任务。后台 worker 需显式运行；没有 worker 时只能显示排队，不能假装预览完成。

**数据用途分离：** 同源原始 RGB、时间、内参与位姿可作为后续研究输入；LiDAR 深度仅在实际采到并上传核验后才能称作云端 RGB-D。FF 产物是查看和质量观察的结果，不能直接推定公制尺度、碰撞网格、机器人仿真可用性或视频模型训练效果。WorldMirror 输出用于改进其他 AI 模型的许可边界需单独审查，原始采集与 FF 派生物保留独立来源记录。传统 SfM 将来读取同一受控原件，新增独立任务和质量报告，不覆盖 FF 结果。

## 交付顺序与验证门槛

| 步骤 | 必须看到的证据 |
|---|---|
| 1. Windows 代码纵切 | v2 核验后可建立 FF 任务；重复请求不重复建任务；其他用户看不到原片、任务或展示文件；worker 导回真实 PLY 后才能为 ready。Node 测试通过。 |
| 2. Mac 构建 | 安装 Xcode、解析依赖、Swift 工程编译和签名成功。记录实际 Xcode／iOS 版本和编译修复。 |
| 3. 一条 iPhone 实拍 | 手机拍摄并保存，原片可播放，逐帧元数据与视频关联；上传后服务端哈希与本机一致。 |
| 4. 真正 FF 预览 | 同一 `captureId` 的 8／16 张选帧、Hub project／step、真实成功状态、PLY 哈希、派生 `.splat` 哈希可串起来；iPhone 能打开并交互。分别记录拍摄、上传、排队、推理、下载、首帧时间。 |
| 5. 极简体验 | 至少 3 位未参与开发的体验者各独立走一遍，记录卡住的步骤、完成时长与是否愿意拍第二处；再迭代引导。 |

当前已用用户指定的 Downloads 水杯视频完成独立 FF 和 SfM → 3DGS 服务器实验，取得真实模型、相机和服务器渲染，但尚未完成 iPhone 原生闭环。正式 FF 转换器仍需按来源适配 WorldMirror 的透明度编码；精细 SH3 下载和手机交互尚未接通。Mac 尚未安装 Xcode，稳定 HTTPS 业务服务与真机查看仍待验收。详见 [视频实测](VIDEO-FF-SFM-COMPARISON-2026-11-03.md)、[双结果与手机验收方案](FF-SFM-MOBILE-DELIVERY.md) 和 [Mac／iPhone 操作步骤](MAC-IPHONE-RUN.md)。
